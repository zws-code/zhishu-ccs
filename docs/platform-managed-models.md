# 平台基础数据、Agent 供应商同步与分组专用 Key

账号服务供应商同步直接复用 Sub2API 已有的用户、分组、Key、模型网关和计费能力。

同步分为两个独立阶段。登录或会话恢复成功后自动尝试一次平台基础数据同步；成功后自动同步全部已支持 Agent 的供应商；账户轮询、窗口重新可见不会重复同步：

1. **智枢平台 → CC Switch 基础数据**：登录后自动尝试一次，也可从侧栏「平台基础数据」点击「同步平台基础数据」。客户端读取当前账号的可用分组、完整订阅记录与专用 Key，按需创建 Key，并获取各分组的模型目录和能力参数。订阅分组不受名称前缀限制，普通按量分组仅同步名称以 `智枢router-ccs-` 开头的分组。该操作只更新本机基础数据，不修改任何 Agent 供应商列表或配置。
2. **CC Switch 基础数据 → Agent 供应商**：在各 Agent 的供应商页点击「同步服务提供商列表」，读取已保存的基础数据，执行对应 Agent 的格式适配和本地供应商对账。该操作不请求平台，不刷新网页登录状态、不创建或撤销平台 Key，也不触发平台额度查询刷新。没有当前账号的基础数据时提示先到基础数据页同步，不会自动联网补齐。

平台页展示当前账号、最近同步时间、分组、模型及部分失败状态。平台整体拉取失败保留上一份快照；分组失败写入失败标记，本地对账沿用既有的失败分组保护，不删除其供应商。平台更新后需在各 Agent 再次点击本地同步才能应用。

列表用紧凑表格区分分组、平台类型、计费类型、模型数与同步状态。点击「查看详情」可打开右侧抽屉，查看分组 ID、用户 ID、分组状态、平台地址、同步时间和 Key ID、名称。API Key 默认遮罩，点击显示或复制时从本机快照单独读取，隐藏或关闭抽屉后不保留明文；Key 不进入前端查询缓存。模型目录与每个模型的参数默认收起，按需展开。参数缺失时显示「未提供」，不从模型名称推测。

详情操作不触发同步或平台请求。常规摘要只包含展示字段白名单，不包含分组 Key 明文、网页登录 token 或模型原始响应。`platform_get_catalog_key({ baseUrl, userId, groupId })` 是显式查看／复制入口，返回当前账号本机快照中的该分组 Key 或 `null`，同时校验当前登录身份、快照归属与分组范围；快照缺失或账号变化时拒绝读取。

IPC：`platform_get_catalog()` 只读本机摘要，返回 `null` 或 `{ baseUrl, userId, syncedAt, groups, warnings }`；`syncedAt` 为 Unix 毫秒。`platform_sync_catalog()` 联网刷新并返回同一摘要。摘要只含分组和模型的展示字段，不含 Key。`platform_sync_providers({ agent })` 保留 `{ added, removed, skipped, warnings }` 返回形状，`agent: null` 仍表示全部支持的 Agent，但数据源改为本机快照。

每个平台分组使用一枚可撤销的专用 Key。同一个账户的分组 Key 跨 Agent、跨设备复用，使用量正常计入当前用户余额。

## 专用 Key

分组与 Key 接口都使用 Web JWT 校验当前用户，不接受设备 ID：

```http
GET /api/v1/groups/available
Authorization: Bearer <web-session-token>
```

```http
POST /api/v1/keys
Authorization: Bearer <web-session-token>
Content-Type: application/json

{"name":"zhishu-ccs-anthropic-42","group_id":42}
```

成功响应：

```json
{
  "code": 0,
  "data": {
    "id": 123,
    "key": "sk-...",
    "name": "zhishu-ccs-anthropic-42",
    "group_id": 42,
    "status": "active"
  }
}
```

客户端按 `name + group_id` 查找当前用户的 Key：

- 有效 Key 直接复用，不重复创建。
- Key 被禁用或过期时创建同名新 Key。
- Key 额度耗尽时保留本地供应商，不使用新 Key 绕过额度限制。
- 不授予新的分组权限，只处理 `/groups/available` 返回的分组。
- 创建 Key 继续受平台原有 Key 数量、频率等防滥用限制。

Key 和网页登录令牌分离。JWT 只用于分组和 Key 管理，不能发往 `/v1/models`。基础数据包含分组模型 Key，保存于设备 `app_local_data_dir()/platform-catalog.json`，隔离开发环境沿用隔离路径；文件通过既有原子写入发布，Unix 权限为 `0600`，不包含网页登录 token，也不进入数据库导出或云同步。快照按 `baseUrl + userId` 校验，其他账号不可读取或应用。

退出登录时，CC Switch 清除会话、本机基础数据中的 Key 明文和当前账户托管 Provider 中的模型 Key，并尝试撤销网页 refresh token。分组、模型参数、订阅归属、Key ID／名称和原同步时间保留，重新登录同一账号仍可查看；前端查询缓存仍随退出清理，再次进入时从本机快照读取。旧版 v1 快照无需重新同步即可读取，正常清理不会更新时间。快照损坏无法解析时会失效化，避免保留无法识别的凭证。

清理后的快照返回 `credentialsCleared: true`，各分组返回 `keyAvailable: false`，页面显示“基础数据已保留，凭证已清除”，隐藏 Key 查看／复制操作。此时 Agent 同步返回 `CATALOG_CREDENTIALS_REQUIRED`，不会把空 Key 写入配置，也不会自动访问平台。登录后的自动同步成功，或手动重试平台基础数据同步成功后，重新获取分组 Key、清除该标记，登录自动流程会继续同步全部 Agent 恢复托管凭证；手动重试基础数据后可点击「全部同步平台供应商」恢复。其他账号仍不能查看或应用这份快照。

## 模型列表与筛选

模型列表直接请求：

```http
GET /v1/models
Authorization: Bearer <dedicated-key>
```

客户端按 Agent 适配器筛选模型协议和能力：

- `/v1/models` 返回 `supported_endpoint_types` 或 `supported_endpoints` 时按其内容判定。
- 统一分组返回合并模型但不带协议明细时，按分组平台网关判定：Anthropic 网关使用 Messages，Gemini 网关使用原生 Gemini，OpenAI 兼容网关使用 Responses。
- 明确标记为非聊天、非流式或不支持工具调用的模型不会展示。
- 需要上下文窗口和输出上限的 Agent 只在平台返回真实数值时提供对应模型。

列表响应缺少可选元数据时按能力未知处理，不从模型名称猜测大小、工具支持或流式能力。

## 同步服务提供商列表

同步不做同步前检测、确认或备份：不比较历史同步基准，外部修改不阻塞同步，也不弹出确认弹窗。`platform_sync_providers({ agent })` 直接按本机目录数据调和托管供应商，全程只访问本机。未变化的托管行不改写原生文件，因此对配置文件的外部编辑会保留；Key 轮换、名称或模型目录变化仍按既有配置适配器与局部写入／恢复逻辑发布，无关设置不受影响。

每次真正执行的同步会在「配置修改记录」中保存一条「平台供应商同步」操作记录，包含供应商新增／更新／删除／未变化数量、同步前后变化的原生文件路径和警告；失败或部分失败同样留痕。供应商仅加入 CCS 列表且未启用时，DSH 等应用的原生文件可能完全不变，此时明确标记“未修改原生配置文件”，不伪造文件差异。真实文件写入仍有原来的前后内容记录，并附带同步操作来源。

同步结果额外返回 `updated` 和 `nativeFilesChanged`，前端刷新配置历史并区分列表更新与文件写入。新的同步不再创建 `backups/platform-sync/` 备份；历史记录中的备份目录仍可通过 `open_config_sync_backup({ id })` 打开，后端仅允许当前设备同步备份根目录中的有效备份，拒绝任意路径。操作记录不能当成单文件快照还原。原来的配置差异记录和安全还原机制不变。

CC Switch 使用本机基础数据中当前账号的可用订阅分组，以及名称以 `智枢router-ccs-` 开头的普通按量分组生成工具供应商。订阅类型依据快照内服务端的 `subscription_type=subscription` 判断，不从分组名称推断。供应商页面顶部提供「同步服务提供商列表」，用于手动刷新当前工具的列表。

每个工具、每个账号、每个平台分组维护一条 `platform-managed-<agent>-<account-scope>-<platform>-<group-id>` Provider。`account-scope` 由平台地址和用户 ID 生成。同步按集合对账：

- 本地供应商和基础数据都存在：不创建重复 Provider；名称、分组信息、上游格式和模型参数跟随基础数据更新；若旧 Key 已被登出清理或轮换，则刷新该托管项的凭证。名称格式为「智枢平台 · 分组名称」，保留本地模型选择、自定义配置和排序。
- 基础数据存在、本地供应商不存在：添加 Provider。
- 本地供应商存在、基础数据不存在：仅清理当前账号已下线的普通按量托管 Provider；已知订阅项保留。
- 只删除带 `platformManaged` 元数据且属于当前 `baseUrl + userId` 的记录，不删除用户自建 Provider，也不修改其他账号的托管记录。

不再符合前缀的旧普通按量分组按下线处理，其本地托管 Provider 在 Agent 同步范围内清理；手动同步单个工具时，其他工具的记录等待各自同步。旧 Key 清理只在「同步平台基础数据」执行：仅处理当前账号由 CC Switch 创建、符合 `zhishu-ccs-<platform>-<group-id>` 命名且 `group_id` 一致的旧分组专用 Key，不删除平台上的普通手动 Key。删除 Key 前检查所有工具的本地供应商；仍被托管项或手动项引用的 Key 保留，避免当前项无法切换、删除失败或其他工具尚未同步时提前撤销凭证。Agent 本地同步释放引用后，旧 Key 等待下一次平台基础数据同步再清理。删除失败通过平台同步警告提示，可再次同步重试。名称符合前缀但暂时停用的分组保留其专用 Key。

平台基础数据同步还读取 `GET /api/v1/subscriptions` 的完整订阅记录，包括到期和暂停的订阅。对应分组的托管 Provider 与专用 Key 不因到期、额度耗尽或名称不符合前缀而删除；Agent 本地同步时，已存在的旧记录会补上 `platformManaged.subscriptionType`。历史记录读取失败时，本次平台同步停止，不进行 Key 创建或清理，上一份本机快照仍可使用。普通手动供应商和其他账号的托管项保持不变。

每个 Provider 使用本机基础数据中该分组下协议兼容的完整模型目录，不主动切换当前供应商。若待删除项正被当前工具使用，会先切换到其他可用供应商；没有备用项时保留并提示用户。Agent 同步只进行本地配置操作，不发起平台或生成请求。

基础模型列表成功刷新后，平台托管 Provider 的模型成员按最新列表更新：增加新模型，移除已下线模型；仍在列表内的模型保留自定义字段和平台未报告的参数，平台明确返回的参数则更新。模型列表获取失败时保留原目录，不当作空列表清除。模型目录更新不会主动替用户更换已选模型；需要先切换模型才能移除当前项的 Agent，沿用其原有拒绝机制并在同步结果中提示。

详细目录按公开模型 ID（包括平台映射别名）与基础列表合并，只补充已授权模型的参数，不扩大模型列表。Codex 写入 `modelCatalog.models` 的 `contextWindow`、`reasoningLevels`、`defaultReasoningLevel` 和输入模态；OpenCode/MCode 写入 `limit`、`reasoning`、`variants` 和输入模态。上游格式使用平台网关协议：例如混合分组走 Responses 桥接，不直接套用 OpenCode Go 的 Chat 格式。

详细目录接口不可用时回退基础列表；未报告的上下文窗口和思考档位留空，已有记录中的这些参数保留，不用固定窗口或档位猜测补齐。模型目录读取失败、沿用本地模型时，也不会覆盖已有目录参数。

## 余额与订阅额度

平台托管 Provider 不通过用量脚本或模型专用 Key 查询账户信息：

- 钱包余额来自 `GET /api/v1/auth/me`，平台账号卡持续展示并允许手动刷新。
- 订阅额度来自 `GET /api/v1/subscriptions/progress`，并以 `GET /api/v1/subscriptions` 补齐到期和暂停记录。客户端按 Provider 的 `platformManaged.groupId` 匹配对应订阅。
- 订阅分组显示每日、每周、每月额度及重置时间；没有配置限额的有效订阅显示为不限量。到期时显示套餐已过期并提供续费入口；暂停、缺少额度进度或查询失败时显示不可用或查询失败，不能退回余额展示或误报不限量。管理订阅入口使用与登录页相同的 `VITE_PLATFORM_WEB_URL`，指向 `/subscriptions`。
- 当前标准分组显示账号级钱包余额，并提示所有按量分组共享该余额。
- 网页登录令牌只在 Rust 进程内使用。额度查询不把 JWT 交给渲染进程、不写入 Provider 配置，也不参与 WebDAV/S3 云同步。

## 当前限制

- `zhishu-ccs-<platform>-<group-id>` 是按账户分组共享的可撤销 Key，不是硬件绑定凭证。
- 统一的模型分组由平台运营配置；客户端不会为了提高模型数量自行扩大权限。
- 真实平台账户的跨 Agent 端到端调用仍需在目标工具版本中验证。
