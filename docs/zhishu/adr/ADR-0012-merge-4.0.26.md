## 目标与选择

吸收上游性能优化、账号计划展示、代理修复、深链扩展及 DSH 目录覆盖，同时保留智枢身份、OAuth2 会话/回调修复、两阶段平台同步、WorkBuddy、配置历史与 ADR-0009 共存隔离。验收要求保留双方祖先、逐块处理冲突、通过相关静态检查及隔离回归，且不改真实用户数据。

整文件采用上游会覆盖智枢补丁；逐提交挑选会遗漏相互依赖并丢失完整上游祖先；选择从当前产品提交建立 `sync/upstream-4.0.26` 三方 merge，按调用链适配。启动调度、DAO 内部无变化写入判断、IPC 阻塞工作和代理转发均在既有核心内部，纯新增模块无法替换这些调用，继续复用上游 Provider、DAO、IPC、路径函数及受控原子写入。

实施文件范围：上游 `App.tsx`/现有 UI 和语言包（L1/L2）、Tauri/依赖/命令注册（L1），Rust commands、database、proxy、settings、DSH 和相关 services（L3），对应前后端测试；准确清单以同步提交相对第一父的 diff 为准。新增本 ADR 和 2026-11-06 同步报告，更新基线、补丁登记、验证记录和索引（L0）。不新增平行核心实现。

## 数据、安全与兼容

保留智枢 0.0.7、独立数据目录、配置归属、代理占位符、Stack/Profile 身份、首写备份和 pending 恢复。平台 OAuth2、Key 生命周期、账号快照和两阶段同步契约不变，不能因前端加载/可见性变化延长后台闲置期限或恢复旧密码登录。新 DSH 目录覆盖沿用上游解析，平台适配继续调用现有路径函数。

本次上游未升级数据库 schema；DAO 批量读取、跳过未变化保存和后台维护须验证不损坏 endpoint、自有元数据、审计与恢复。新设备设置沿用既有序列化。依赖主要为上游 Tauri CLI 的既有依赖升级，不增加自有运行时依赖。上游源命令变 async 时需同步 facade 和直接调用测试，保持 IPC 名称、参数、错误与返回形状。

产品历史在此前任务已线性整理，本轮以当前 HEAD 为准，不重写历史，不处理 `origin/ccs-dev` 既有分歧，不推送或发布。既有未跟踪 `.agents/`、`.dsh/`、`.omp/`、`.opencode/`、`.pi/`、`.zcode/`、`openspec/` 不纳入提交或清理。保留上游文件/兼容入口；上游自身替换逻辑按其变更意图逐块复核，不借合并执行额外清理。
