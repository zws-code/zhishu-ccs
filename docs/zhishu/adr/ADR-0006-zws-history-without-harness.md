# ADR-0006：整理 zws 二开历史并移除 Harness 接入

> 适用范围：仅适用于当时独立整理分支。当前已合入上游 4.0.22 的 DSH 原生适配并接入平台同步，见 ADR-0007 和功能说明。

- 日期：2026-10-31
- 状态：独立整理分支，未合并或发布
- 范围：L0 自有模块及测试；L1 应用、IPC、翻译入口；L3 ProviderService、配置适配和平台同步中的枚举分支
- 基线：官方 CC Switch `c4db63c6`（4.0.21）

## 场景与验收

从 `ccs-dev` 提取作者为 `zws <447643445@qq.com>` 的二开成果，按上游修改和功能归属重组 Git 提交。新分支保留官方祖先和 WorkBuddy、平台登录、目录同步、配置历史及发行能力；不包含二开新增的 DeepSeek Harness 应用接入。官方原有的 DeepSeek 模型和供应商预设继续保留。

验收以新分支最终文件树为准：没有 Harness 应用 ID、IPC、配置写入和前端入口；前后端白名单一致；TypeScript、Rust 编译及相关回归通过。既有 `ccs-dev`、发布 tag 和远程分支不变，不推送。

## 方案与取舍

以官方 4.0.21 为父节点，按最终代码归属建立新的分组提交。已发布提交不能原地重写；旧 SHA 保留在 `ccs-dev` 和 tag 上。混合提交 `6ea73696` 只提取 WorkBuddy 的最终实现，Harness 部分不进入新分支。上游已有文件的接线集中在兼容补丁提交，智枢业务仍位于自有命名空间。

未选择删除整个混合提交：会同时丢失 WorkBuddy。未选择在旧历史后追加删除提交：新历史仍会包含 Harness 接入代码。分组提交按文件归属构造，最终文件树经过验证；中间快照不作为独立发布版本。

## 数据与跨平台影响

此整理不执行应用、CLI 或数据库迁移，也不删除用户机器上的 `.dsh` 文件、历史备份或旧数据库行。新分支不再识别 Harness 应用 ID；已有 Harness 数据需在原发布版本管理或迁出。WorkBuddy 和其他工具路径仍按原有覆盖规则解析。macOS、Windows、Linux 真机安装、原生 CLI 启动及升级尚需单独验收。

## 回退与验证

回退只需切回未改动的 `ccs-dev` 或对应发布 tag；不移动 tag，不强推共享分支。验证记录见 `docs/zhishu/history/validation.md`。上游补丁登记保留历史条目，并在本分支追加本次移除范围说明。
