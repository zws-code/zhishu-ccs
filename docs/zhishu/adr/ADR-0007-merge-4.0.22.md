# ADR-0007: 合并上游 4.0.22 并保留智枢边界

- 日期：2026-10-31
- 状态：待评审；本 ADR 不构成发布批准
- 等级：L3（应用枚举、Provider 服务、代理分派及数据库迁移）
- 上游：`4.0.22`，`b76426741ef93069e2f374ac01ca7ef5760e1d0e`

## 背景与目标

智枢分支从上游 4.0.21 基线继续同步 4.0.22。上游新增 DSH 和 v24 数据库迁移；智枢已有 WorkBuddy、平台会话与目录、配置历史、独立产品身份。合并后必须同时保留双方能力，并让旧库可按既有迁移事务升级。

## 备选方案

1. 整文件采用上游：丢失智枢应用身份、WorkBuddy 和平台入口。
2. 整文件采用智枢：丢失 DSH 分派、`subtle` 依赖与 v24 迁移。
3. 按三方索引逐块合并，保留上游服务及页面流程，仅在穷举入口补 WorkBuddy/DSH 和自有 UI 挂载。

选择方案 3。应用枚举、Rust `match`、既有数据库迁移入口和页面内状态无法仅靠新 Adapter 补全；平台业务仍调用自有模块与上游 Provider 服务。供应商列表恢复上游归属判断及错误提示；页面恢复上游 `refreshAdditiveLiveState`，分支已有的 `useTauriEvent` 监听保持不变。自有归属 Hook 继续供平台批量按钮使用。应用身份与版本保持智枢 `0.0.3`，4.0.22 仅记录为上游基线。

## 兼容性与风险

- v23 库升级到 v24 时补 `enabled_dsh` 和会话游标 `parser_state`，继续幂等补齐智枢 v23 的 `enabled_omp`。旧 OMP/Kimi 标记、端口和游标不得被覆盖。
- WorkBuddy 继续走独立局部写入与恢复路径；DSH 复用上游 `dsh_config::save_and_commit`。代理不得把两者误作 Codex 适配器。
- Keyring、平台 token 与原生 CLI 凭据路径不因本合并迁移。Windows/Linux 原生运行、CLI 实机、安装与更新需另行验收。

## 验证与回退

验证范围见 [同步报告](../upstream-sync/2026-10-31.md)：前端类型/测试、Rust 格式/编译及隔离目录测试，包含数据库 v23/v24、Provider、DSH 和平台页面。回退在独立合并分支撤销合并提交；已打开升级到 v24 的真实数据库只能用升级前备份恢复，旧客户端不能直接读取新 schema。保留上游祖先，不强推已发布分支。

复审日期：下一次发布候选版验证前。
