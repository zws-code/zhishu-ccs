# ADR-0010：移除开发启动隔离

- 日期：2026-11-03；状态：按用户“去掉开发隔离相关代码”授权实施；实际验证另记，不代表发布批准。
- 等级：L0 自有启动脚本、平台存储与文档；L1 package/启动接线；L3 既有路径分派撤回。

## 场景与验收

开发启动沿用正常数据和工具配置路径，移除专用开发目录、Codex 初始化及后端强制目录覆盖。按用户进一步要求减少脚本，通用启动和进程管理直接复用 Tauri CLI；测试专用 `CC_SWITCH_TEST_HOME` 保留。2026-11-03 后续要求同时移除自有 macOS 开发签名入口及测试。旧开发数据不迁移或删除，平台凭据不改存储方式。

## 选择与备选方案

删除 `scripts/zhishu/dev-isolated{,.test}.mjs`，不保留通用启动器或其测试。`package.json` 的 `dev` 直接使用 `tauri dev`，不再提供自有 `--dry-run`、遗留 Vite 清理或 `test:dev` 命令。后续按用户要求删除自有 macOS 开发签名脚本、对应测试与命令入口，不新增替代脚本。

移除 `config.rs` 的开发 home 解析及应用/设备目录分支、`codex_config.rs` 的强制开发目录、`lib.rs` 的隔离日志；平台文件入口统一复用 Tauri `app_local_data_dir()`。这些分支在上游函数内部优先执行，单独增加 Adapter 无法撤回行为，因此必须删除自有分支；保留上游函数、设置目录覆盖、Windows 兼容回退、原子写入和备份/pending 流程。

备选：仅停用启动脚本会留下后端环境变量入口；保留开关不满足移除相关代码；另留通用包装层增加维护成本。选择直接复用 Tauri CLI，并撤回全部专用隔离分支。原先保留的 macOS 签名辅助选项按后续要求移除。

## 数据、安全与跨平台边界

本决策按用户本次指令替代 AGENTS 中的开发隔离说明，不改变测试隔离要求。正常数据路径上的设置、数据库、平台目录和 keyring 凭据可能重新显示；旧开发目录的登录不会自动迁入。保留凭据 ID 的存储目录摘要，不读取或搬运旧 keyring 条目，不创建明文凭据兜底。

不更改应用身份、单实例、发布、更新或原版共存机制。各平台直接使用 Tauri CLI 开发启动，OAuth2 系统凭据库与自动恢复保留；macOS 开发版重编译后仍可能要求重新授权钥匙串访问。开发版随后执行的用户操作会作用于正常配置。移除不会主动写入真实用户配置或数据库。

## 验证与回退

使用临时目录验证 Codex 默认目录、设置覆盖优先级、设备目录和未知配置内容保留；Rust 相关回归已执行，结果见[验证记录](../history/validation.md)。开发入口收敛及后续签名脚本删除检查命令指向、Tauri CLI 帮助与引用，避免启动真实应用或访问 keyring。上一轮包装层与签名测试结果仅记录当时实现。

回退代码时恢复旧启动器、命令及开发路径分支，再显式选择原有开发目录；不自动搬移、合并或删除任何现有数据。移除期间正常配置的用户修改通过既有配置历史/备份恢复，恢复前保留当前内容，不全量覆写目录。复审日期：2026-11-03，按本轮检查结果更新。
