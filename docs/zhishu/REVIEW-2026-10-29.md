## 存量风险与后续范围

1. **平台 Key 持久化不符合安全标准**：`CatalogStore::save` 将含 `GroupCredential.key` 的目录序列化为 `platform-catalog.json`，`atomic_write_private` 仅设置 Unix 0600 并原子写入，不提供加密；上游 Provider/CLI 配置及配置历史还可能保留凭据副本。这与 ZCCS-DEV-001 §4.2 的系统安全存储要求冲突。本轮没有迁移数据，不能据此认定满足生产凭据保护要求。
   建议先建立专门 ADR：梳理目录、Provider、历史/备份及导出中的凭据副本；目录改存账户作用域的凭据引用，Key 放入系统凭据库；旧 v1 目录先写入并读回验证凭据，再原子提交无明文快照，迁移失败保留可恢复状态并报告；确定旧客户端回退和备份访问策略。必须覆盖凭据库锁定、部分失败、账号切换、macOS/Windows 迁移及恢复，不能只给 JSON 换扩展名或删除旧文件。
2. Windows 便携版仍有上游下载地址 TODO；本轮未调整自动更新协议，正式便携版发布前需要独立配置和签名/下载回归。
3. 远程命名与规范不一致（`origin` 指向官方，智枢仓库为另外两个 remote）；本轮只建立修复分支，未调整远程、提交、推送或发布。
