## 冲突处理

`git merge v4.0.40` 产生 37 个冲突文件：CI、CONTRIBUTING、package/Cargo 清单与锁、`tauri.conf.json`、`codex_config`、`commands/misc`、`database/backup`、`deeplink/tests`、`dsh_config`、`lib.rs`、`live/project/claude`、`mode/controller`、`mode/stack`、`panic_hook`、`proxy/forwarder`、`proxy/providers/codex`、`proxy/types`、`backup_storage`、`env_manager`、`services/skill`、`tray`、`App.tsx`、`ProviderCard`、`WebdavSyncSection`、八个语言 JSON、`navigation.ts`、`types.ts` 与 `useDirectorySettings` 测试。

处理方式：主线 `ccs-dev` 与本分支的自有代码同源（主线 0.0.11 之后没有二开功能提交），差别只在 WorkBuddy 与 v4.0.33 重建时的少量适配，因此除文档和 `AGENTS.md` 外，所有路径先取主线 `3231ad64f` 的合并结果（含其对 v4.0.37/v4.0.40 全部冲突与自动合并的处理），再按本分支规则去掉二开 WorkBuddy：

- 删除 `zhishu/integrations/ccswitch/workbuddy.rs`、`workbuddy_config.rs`、`src/zhishu/tools/workbuddy/` 及两组测试；
- 上游文件中的二开接线还原为上游：`commands/provider.rs` 两个 IPC、`lib.rs` 启动导入与注册、`services/provider/mod.rs` 旧适配分派（含随之改写的 `matches!` 与校验分支位置）、`live.rs` 启动跳过与说明、`stream_check.rs` 分支、`commands/workbuddy_account.rs` 归属查询、`EditProviderDialog`、`ProviderList`、`mutations.ts` 失败补刷、`lib/api/{providers,types}.ts`；
- 二开 WorkBuddy 表单的 `workbuddy.*` 文案从八语中移除；
- merge 提交中上游 `workbuddy_config.rs` 与 v4.0.40 一致，设置页目录覆盖与归属字段补丁放到 fix 提交；`deeplink/tests.rs` 的 WorkBuddy 断言在 merge 提交中按上游 `ccSwitchProviderId`，fix 提交改为 `zhishuCcsProviderId`；
- 平台同步对 WorkBuddy 的适配沿用 4.0.33 分支（上游格式、完整 `/chat/completions` 地址、条目不带 Key），改写到主线新的 DAO 签名上。

由此继承的主线取舍（非 WorkBuddy）包括：schema 27、`appConfig` 兼容导出（自有代码继续用 `isModeAppId` 等）、保留上游删除的 `claude.yml` 与 `ui/tabs`（平台分组详情回到 Tabs 组件，不再是 4.0.33 分支上的 `PageTabs` 改写）、主线的德语文案（智枢键为英语回退，4.0.33 分支的机器翻译不再保留）、保留上游删除的若干文案键、AppsPage 的“手动管理”分组等。
