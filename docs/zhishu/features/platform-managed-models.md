# 平台基础数据、Agent 供应商同步与分组专用 Key

> 2026-10-31：客户端源码已按 [专用接口接入契约](../api/client-api.md) 改造。Key 生命周期由网关负责；验证范围见 [验证记录](../history/validation.md)，不代表真实平台或跨平台验收已完成。

账号服务供应商同步直接复用 Sub2API 已有的用户、分组、Key、模型网关和计费能力。

同步分为两个独立阶段。登录或会话恢复成功后自动尝试一次平台基础数据同步；成功后自动同步全部已支持 Agent 的供应商；账户轮询、窗口重新可见不会重复同步：

1. **智枢平台 → CC Switch 基础数据**：登录后自动尝试一次，也可从侧栏「平台基础数据」点击「同步平台基础数据」。客户端仅调用 `POST /api/zhishu/v1/client/access` 获取服务端授权分组、专用 Key、连接地址、模型目录和额度状态；不自行推断前缀授权、查找或管理 Key。该操作只更新本机基础数据，不修改任何 Agent 供应商列表或配置。
2. **CC Switch 基础数据 → Agent 供应商**：在各 Agent 的供应商页点击「同步服务提供商列表」，读取已保存的基础数据，执行对应 Agent 的格式适配和本地供应商对账。该操作不请求平台，不刷新网页登录状态、不创建或撤销平台 Key，也不触发平台额度查询刷新。没有当前账号的基础数据时提示先到基础数据页同步，不会自动联网补齐。

平台页展示当前账号、最近同步时间、分组、模型及部分失败状态。平台整体拉取失败保留上一份快照；分组失败写入失败标记，本地对账沿用既有的失败分组保护，不删除其供应商。手动刷新平台基础数据后需再次执行本地供应商同步才能应用；登录/恢复时的自动流程会依次完成两个阶段。

列表用紧凑表格区分分组、平台类型、计费类型、模型数与同步状态。点击「查看详情」可打开右侧抽屉，查看分组 ID、用户 ID、分组状态、平台地址、同步时间和 Key ID、名称。抽屉分为「分组概览」和「模型目录」两个页签：概览分卡展示基本信息、额度状态、订阅周期用量与 API Key；模型目录可按名称或 ID 本地筛选，显示匹配数量，每个模型的参数按需展开。API Key 默认遮罩，点击显示或复制时从本机快照单独读取，隐藏、切换到模型页签或关闭抽屉后不保留明文；Key 不进入前端查询缓存。参数缺失时显示「未提供」，不从模型名称推测。标题和页签固定，概览与模型列表各使用单一正文滚动区域，避免嵌套滚动阻断鼠标滚轮。

详情操作不触发同步或平台请求。常规摘要只包含展示字段白名单，不包含分组 Key 明文、网页登录 token 或模型原始响应。`platform_get_catalog_key({ baseUrl, userId, groupId })` 是显式查看／复制入口，返回当前账号本机快照中的该分组 Key 或 `null`，同时校验当前登录身份、快照归属与分组范围；快照缺失或账号变化时拒绝读取。

IPC：`platform_get_catalog()` 只读本机摘要，返回 `null` 或 `{ baseUrl, userId, syncedAt, groups, warnings }`；`syncedAt` 为 Unix 毫秒。`platform_sync_catalog()` 联网刷新并返回同一摘要。摘要只含分组和模型的展示字段，不含 Key。`platform_sync_providers({ agent })` 保留 `{ added, removed, skipped, warnings }` 返回形状，`agent: null` 仍表示全部支持的 Agent，但数据源改为本机快照。

每个平台分组使用一枚可撤销的专用 Key。同一个账户的分组 Key 跨 Agent、跨设备复用，使用量正常计入当前用户余额。

## 专用 Key

获取专用 Key 的唯一入口是 `POST /api/zhishu/v1/client/access`，使用当前会话的 access token，请求不指定用户、分组、Key 名称或额度。服务端负责分组授权和共享 Key 的整理；客户端没有 Key 列表、创建、替换、撤销或旧 credentials 回退代码。目录失败、Key 过期或额度耗尽都不会触发客户端补偿建 Key。

Key 和登录令牌分离。快照版本为 **2**，按平台地址和用户 ID 分别保存于设备 `app_local_data_dir()/platform-catalogs/<账号摘要>.json`，开发隔离沿用已有路径。有效的旧单文件 v2 快照仅在归属匹配时迁移，先原子写入再移除旧文件；不同账号不会覆盖彼此。复用私密原子写入，Unix 权限 `0600`；快照不包含 JWT，不进入数据库导出或云同步。`syncedAt` 来自服务端 RFC3339 时间转 Unix 毫秒。版本 1 或其他旧版本只读返回无目录，不迁移字段、不接管旧凭证，也不自动删文件；需重新同步。

摘要中的 `keyAvailable` 仅表示凭证明文存在，与 `quota.available` 独立；`quota.reasons`、`subscriptions` 和不含 Key 的 `credential` 元数据用于展示过期、禁用、余额及周期额度状态。整体请求或格式校验失败保留原快照；成功空分组才代表当前授权集合为空。单组模型失败记录 `failed`，不会借用其他本地模型扩大授权范围。

普通退出只清会话、系统凭据库登录条目和前端缓存，保留目录、Provider 和工具配置中的模型 Key。未登录不能读取或同步这些平台数据；重新登录同一账号可读取版本 2 快照。显式本地 Provider 删除也不会删除共享 Key。旧显式凭证清理代码、清理状态和占位凭证已移除；分组无凭证使用 `keyAvailable: false` 和服务端 `quota.reasons` 展示。损坏或目录项凭证明文为空的本机快照拒绝读取并保留原文件；需重新同步获取有效数据。


账号菜单另提供「退出并清除此账号本机数据」，确认后删除当前账号的目录、全部支持应用中的平台托管供应商（含隐藏应用），最后清理会话并尝试撤销本次 refresh token。无安全备用项的当前供应商和失败项保留，退出后用可关闭弹窗显示逐应用及各步骤结果，不占用登录表单布局。登录账号记录、服务器地址和已记住密码保留，由登录页原有入口单独管理。其他账号、自建供应商、授权中心账号、配置修改记录及恢复备份保留，不删除共享服务端 Key；这不是磁盘安全擦除。旧单文件归属无法判断时保留并报告未完成。重新登录后的自动同步可能重新创建平台目录和供应商。

页面明确显示当前账号邮箱、平台地址和用户 ID，仅展示当前已验证账号；账号变化卸载详情与明文 Key 状态。这里的账号区分仅指数据存储与展示隔离，仍只有一个活动登录会话。存储迁移、清理边界和回退见 [ADR-0005](../adr/ADR-0005-account-local-cleanup.md)。

## 模型列表与筛选

模型及能力全部来自 `/access` 的 `groups[].models`；客户端不再请求模型列表或 Codex 能力清单。模型 ID 缺失、快照版本不支持或身份不匹配会拒绝整个快照。`ok + []` 与 `failed + null` 分别处理。

只保留服务端授权模型 ID 和白名单能力字段，缺失的上下文、输出上限、工具/流式支持和思考档位保持未知。模型中明确报告的协议优先用于各工具适配，`connection.endpoints` 仅用于连接路径，不能作为模型能力。部分原生工具要求具体布尔值或窗口大小时，仅在适配输出中使用明确的本地默认策略，不写回平台摘要或快照。

`connection.base_url` 与登录平台地址独立，空值回落登录平台 origin；JWT 始终只发送给登录平台。各工具继续按原生协议补路径；当前支持标准协议后缀及额外公共路径前缀，不可表达的协议路径返回适配警告并保留已有供应商，不猜测另一个地址。生成的网关根记录在 `platformManaged.connectionBaseUrl`；网关变更只更新仍匹配上次生成地址的字段，保留用户自定义 URL 和 TOML 注释。

## 同步服务提供商列表

同步不做同步前检测、确认或备份：不比较历史同步基准，外部修改不阻塞同步，也不弹出确认弹窗。`platform_sync_providers({ agent })` 直接按本机目录数据调和托管供应商，全程只访问本机。未变化的托管行不改写原生文件，因此对配置文件的外部编辑会保留；Key 轮换、名称或模型目录变化仍按既有配置适配器与局部写入／恢复逻辑发布，无关设置不受影响。

每次真正执行的同步会在「配置修改记录」中保存一条「平台供应商同步」操作记录，包含供应商新增／更新／删除／未变化数量、同步前后变化的原生文件路径和警告；失败或部分失败同样留痕。供应商仅加入 CCS 列表且未启用时，累加式应用的原生文件可能完全不变，此时明确标记“未修改原生配置文件”，不伪造文件差异。真实文件写入仍有原来的前后内容记录，并附带同步操作来源。

同步结果额外返回 `updated` 和 `nativeFilesChanged`，前端刷新配置历史并区分列表更新与文件写入。新的同步不再创建 `backups/platform-sync/` 备份；历史记录中的备份目录仍可通过 `open_config_sync_backup({ id })` 打开，后端仅允许当前设备同步备份根目录中的有效备份，拒绝任意路径。操作记录不能当成单文件快照还原。原来的配置差异记录和安全还原机制不变。

CC Switch 使用服务端成功下发的授权分组生成工具供应商，不再做客户端名称前缀过滤。订阅归属使用服务端订阅关联与订阅类型，保留过期或暂停但仍在快照中的分组。供应商页面顶部提供「同步服务提供商列表」，用于手动刷新当前工具的列表。

每个工具、每个账号、每个平台分组维护一条 `platform-managed-<agent>-<account-scope>-<platform>-<group-id>` Provider。`account-scope` 由平台地址和用户 ID 生成。同步按集合对账：

- 本地供应商和基础数据都存在：不创建重复 Provider；名称、分组信息、上游格式和模型参数跟随基础数据更新；若新快照返回的共享 Key 已变化，则刷新该托管项的凭证。名称格式为「智枢平台 · 分组名称」，保留本地模型选择、自定义配置和排序。
- 基础数据存在、本地供应商不存在：添加 Provider。
- 本地供应商存在、基础数据不存在：按成功快照清理当前账号已撤销授权的托管 Provider；仍有授权但额度不可用或目录失败的项保留；成功且可用的空模型目录按无授权模型处理。
- 只删除带 `platformManaged` 元数据且属于当前 `baseUrl + userId` 的记录，不删除用户自建 Provider，也不修改其他账号的托管记录。

授权范围、共享 Key 删除与分组前缀规则由服务端统一决定。客户端只协调当前账号本机 Provider，不做旧 Key 引用扫描或远程回收；手动供应商与其他账号记录保持不变。

每个 Provider 使用本机基础数据中该分组下协议兼容的完整模型目录，不主动切换当前供应商。若待删除项正被当前工具使用，会先切换到其他可用供应商；没有备用项时保留并提示用户。Agent 同步只进行本地配置操作，不发起平台或生成请求。

基础模型列表成功刷新后，平台托管 Provider 的模型成员按最新列表更新：增加新模型，移除已下线模型；仍在列表内的模型保留自定义字段和平台未报告的参数，平台明确返回的参数则更新。模型列表获取失败时保留原目录，不当作空列表清除。模型目录更新不会主动替用户更换已选模型；需要先切换模型才能移除当前项的 Agent，沿用其原有拒绝机制并在同步结果中提示。

模型能力直接使用 `/access` 的明确返回值。Codex 写入已报告的窗口、思考档位和模态，OpenCode/MCode 写入已报告的 limit、reasoning、variants 等；未报告参数沿用已有记录，不进行另一套网络发现。目录失败只保留现有供应商，不新建使用未知授权模型的供应商。

DeepSeek Harness (`dsh`) 复用上游的增量 Provider 和原生 profile 适配。平台目录只映射 Anthropic Messages、OpenAI Responses 与 Chat Completions；Gemini 原生协议不生成 DSH 模型。同步新建托管项时通过 ProviderService 同时写入 DSH profile 和凭据引用；已有托管项若原生 profile 缺失，重复同步会补写。DSH 模型的思考档位只写入原生 schema 支持的值；再次同步会清理旧托管项中不支持的档位。原生写入失败时返回警告，不把未发布项误报为成功添加。未变化的原生文件不改写；Key 或模型目录变化时只更新该账号托管项，删除仍按账号归属执行。DSH 的 `DSH_HOME`、profile 锁、私密凭据文件和失败恢复沿用上游实现。当前 macOS 本机的 DSH 模型选择器已确认显示平台分组；跨平台及模型请求仍需验收。

## 余额与订阅额度

平台账户刷新仅调用 `GET /api/zhishu/v1/client/account`；额度刷新仅调用 `GET /api/zhishu/v1/client/usage/summary`，不整理 Key 或更新 `/access` 快照。

`platform_get_subscription_usage` IPC 返回 `{ baseUrl, userId, syncedAt, balance, groups }`，嵌套分组、窗口和订阅字段保持客户端协议的 snake_case；不包含 Key、连接或模型。前端五分钟刷新，按平台地址和用户隔离，取消或身份不匹配的迟到响应不能进入缓存。多条订阅分别保留；仅对有效、未过期且分组可用的订阅显示不限量。Key 缺失、过期、禁用、额度耗尽、订阅暂停及余额不足单独展示；缺失分组或查询失败不回落余额。

注册、找回密码和订阅管理网页地址来自 `/config`，相对路径按平台 origin 解析，关闭开关则隐藏对应入口。

## 当前限制

- 多设备共享同组 Key 的一致性取决于服务端 `/access` 实现，客户端模拟回归不能代替真实平台验收。
- 原生配置写入继续由既有 ProviderService、应用锁、原子发布及恢复路径负责；本次不改通用写入引擎。
- 系统 keyring、真实 CLI 运行、跨版本升级及 Windows/Linux 实机尚需专项验收。本次不发布安装包。

自动供应商同步的兼容性警告和配置错误通过浮动提示展示，并保留现有配置修改记录；不写入平台基础数据页的目录错误状态。目录本身的读取或同步失败仍在基础数据页提示。

平台基础数据页的「一键删除平台供应商」使用独立可关闭弹窗反馈成功、部分失败或错误，不在目录正文保留结果表格/错误段落，也不重复弹出 toast。弹窗显示删除/保留数量，逐应用明细默认折叠，关闭后清空本次结果；切换账号或退出后的旧响应不再显示。应用页菜单的原有 toast 行为保留。
